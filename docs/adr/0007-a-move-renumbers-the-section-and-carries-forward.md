# A move renumbers the section and carries forward from the current period

A line is moved by long-pressing its title and dragging it; there is no grip handle and no star (#29, #86). A section reads in `sortOrder` alone, so a move is a write to `sortOrder`: `moveEntry` renumbers that period's lines 1… in the new order and stamps only the lines whose place changed. Templates materialize only into the current period (ADR 0001), so nothing else would take an order to the next page; a move on the period containing today therefore carries forward, giving every recurring line's template its line's place. A move on a past page stays on that page: its lines are not the ones the next period is written from. A retired template is never written.

Rejected: a midpoint `sortOrder` that writes only the moved line. A page's numbering and its templates' are not the same numbers (retiring the star renumbered pages, not templates, and removals leave gaps), so one number written through to one template can land it anywhere among the others. Renumbering the page and giving every recurring line's template that number is the one rule under which the next period matches the page by construction. Templates not on the page, a daily one whose weekdays skip today, keep their place and can tie with a renumbered one; ties read in stored order.

Under the merge (ADR 0005) each renumbered line is a whole write: a move made later on one device beats a check tapped earlier on a displaced line on another, the same limit as two devices tapping one line. Stamping only what changed keeps that to the lines between the old place and the new.

The gesture never reorders anything while a finger is down. The lifted row leaves the flow and follows the finger; the others keep their order and open its slot with a margin, sliding by a layout transition; the store moves only once the drop has settled, in one commit that also remounts the dropped row. Reordering the views mid-drag would take the touch from the row being dragged, and a drag offset held on the UI thread cannot be cleared in the same frame as a React commit, so the offset leaves with the old view instead. Rows are measured, never assumed to share a height. VoiceOver and keyboard users move a line with the title's Move up and Move down actions, and on web with Alt+↑ and Alt+↓.
