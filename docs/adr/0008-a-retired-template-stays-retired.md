# A retired template stays retired, and a stopped goal keeps its line

Turning Repeats off on a recurring line stops the goal without crossing the line off (#89). `stopRepeating` sets `retiredAt` on the template and stamps the line; the line keeps its id, its checks and its `templateId`, and nothing else is rewritten. A stamped line is never a ghost (ADR 0005 drops only untouched lines on periods after the retirement), so the kept line survives every merge, including a stale device's copy of it and a later write to it there. Retirement is permanent: `mergeGoals` gives each template the earliest `retiredAt` either copy holds, whichever copy's write is later, so an edit made on a device that had not heard of the stop (a rename, a new check count, a new weekday schedule) keeps its content and still leaves the goal stopped. It is the one field ADR 0005's later-write-wins rule does not decide. A template retired twice (stopped and then its kept line removed, or retired on two devices) keeps its first retirement, so the ghost rule's cut-off never moves later. A stopped template does not start again. Turning Repeats on in a line's edit form, on a one-off line or on one kept from a stopped goal, starts a new template from that line (`startRepeating`): it takes the line's title, check count, labels and place, and the line, stamped, becomes its entry on that period. Every device gives that template the same id, the line's id and the count of templates started from it, so a line started on two devices repeats once. A template is never materialized onto the period of the line it was started from, so a stale copy of that line winning a merge puts no second line beside it; Repeats turned on again there links the line to the template already started, which takes the line's shape and the weekdays chosen. Nor is it materialized onto a period where that line was already carried over. Two devices starting the same line share one template, so its retirement on one stands on both: a line started and stopped on one device, and started on another that had not heard, stays stopped, reads Repeats off, and starts its next template when Repeats is turned on again.

Rejected: dropping `templateId` from the kept line, which makes it a one-off that a stale device's later write turns back into a recurring line, and that carryover (#58) would offer on the next page of a goal just stopped; leaving the merge rule alone, where a stale device's edit, being the later write, un-retires the template on every device with nothing on screen saying so; and reviving a retired template when Repeats is turned back on, which needs retirement to be reversible in a merge and so a stamp of its own.
