# A retired template stays retired, and a stopped goal keeps its line

Turning Repeats off on a recurring line stops the goal without crossing the line off (#89). `stopRepeating` sets `retiredAt` on the template and stamps the line; the line keeps its id, its checks and its `templateId`, and nothing else is rewritten. A stamped line is never a ghost (ADR 0005 drops only untouched lines on periods after the retirement), so the kept line survives every merge, including a stale device's copy of it and a later write to it there. Retirement is permanent: `mergeGoals` gives each template the earliest `retiredAt` either copy holds, whichever copy's write is later, so an edit made on a device that had not heard of the stop (a rename, a new check count, a new weekday schedule) keeps its content and still leaves the goal stopped. It is the one field ADR 0005's later-write-wins rule does not decide. A template retired twice (stopped and then its kept line removed, or retired on two devices) keeps its first retirement, so the ghost rule's cut-off never moves later. A stopped goal does not start again: the goal is written anew with Repeats on, as a new template.

Rejected: dropping `templateId` from the kept line, which makes it a one-off that a stale device's later write turns back into a recurring line, and that carryover (#58) would offer on the next page of a goal just stopped; leaving the merge rule alone, where a stale device's edit, being the later write, un-retires the template on every device with nothing on screen saying so; and reviving a retired template when Repeats is turned back on, which needs retirement to be reversible in a merge and so a stamp of its own.
