# The feedback token is typed in by the user and kept in the Keychain

A feedback note is filed as a GitHub issue from inside the app (#60), and the app has no backend to hold a credential for it. The one user pastes a fine-grained GitHub token, scoped to this repo with Issues read and write, into the feedback form once. It is kept in the iOS Keychain through `expo-secure-store`, readable only while the device is unlocked and left out of backups and device transfers (`WHEN_UNLOCKED_THIS_DEVICE_ONLY`); on web, where there is no Keychain, it sits in `localStorage`. The token lives outside every zustand store, so it is never in the pad file and never synced; each device gets its own paste. Without a token, Send opens GitHub's new-issue page with the note filled in, so the feature works with no credential at all.

The vision's "no keys, no backend" principle is about model access, and stands: this is a token the user creates, scopes and can revoke, typed into a personal app, not a key the build carries. Rejected: a token baked into the build, which anyone holding the bundle can read; a backend or GitHub App that holds the credential, which is the server the app does not have; and the OAuth device flow, which needs a registered app and a sign-in screen for one user and one repo. `expo-secure-store` asks for no Face ID usage string here (`faceIDPermission: false`), because the token is stored without `requireAuthentication`.
