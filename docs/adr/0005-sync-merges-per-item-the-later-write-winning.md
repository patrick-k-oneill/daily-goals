# Sync merges the pad per item, the later write winning, with tombstones for removals

Every device holds a full copy of the pad and reconciles by merging, never by overwriting (#6). Each template, entry and event carries `updatedAt`, and a gratitude entry its `writtenAt`: the stamp of the last write, from the writing device's clock. Merging is per item, keyed by id (templates, entries, events) or reflection date (gratitude): the later stamp wins whole; a tie goes to a canonical comparison of the content so every device picks the same copy; and the result is sorted by key, so a merge is the same whichever side is local and a device with nothing new has nothing to push. A removal leaves a tombstone, the key and when: a tombstone at or after an item's stamp removes it, and an item written after its tombstone revives it and spends the tombstone. Identity is deterministic so that two devices writing the same morning produce one line: a materialized entry's id is `<templateId>:<periodKey>`, a seed template's is `seed:<cadence>:<sortOrder>`, a line nobody has written on is stamped the epoch (so any real write beats an untouched copy), and materialization skips tombstoned ids. Retiring a template records `retiredAt`; an untouched line on a period that began after the retirement is a ghost a stale device wrote before it heard, and every device drops it the same way, no tombstone needed. Data from before stamps (goals store v2, gratitude and events v1, pad file schema 1) is stamped the moment it arrives on a device, with retirements at the epoch and seed and materialized ids rewritten, so an upgraded pad wins over a fresh device's seed.

Rejected: per-check merging, which needs a stamp per check and would roughly double the goals store (ADR 0004) — so the same line tapped on two offline devices keeps only the later device's marks, a known limitation whose upgrade path is a three-way merge against a stored base; and replace-on-conflict, which is a merge that drops data, the failing test. Concurrent writes to the cloud converge without coordination: whichever copy iCloud keeps, each device pulls it, merges, and pushes only if its pad differs from the last cloud content it saw, so two rounds settle it.
