# A section settles before it is achieved, and only a check tap starts it settling

A check cycles empty → done → missed, so marking the last goal of a section missed passes through "every check done" (Issue #94). The "Achieved!" header and the reward moment must not show on that pass, and the tap interaction is not to change. So a section a check tap completes is **settling** for `SETTLE_MS` (1.5 s) before it reads as achieved: `settleAfterTap` starts it from the tap's moment, any tap that leaves the section incomplete stops it, and `settleSection` ends it once the tap has rested, with the clock passed in. The header component only schedules against these: it sets a timer from `msUntilSettled` and acts on the outcome `settleSection` returns.

Settling is started by the goals store's `cycleCheck` action and by nothing else, which is what keeps the reward moment causal. A section completed by a rehydrate, an import or a merge was never settling, so it is achieved at once and plays nothing. The state lives in a second store, `useRewardsStore` (`settling` by period key, and `played`, the last period each cadence's reward moment played on), because it is this device's memory and not the pad: it is in no pad file and no merge, and rehydrating it drops whatever was still settling. `played` is persisted so that "once per period per section" survives iOS evicting the app mid-day. The reward moment plays only on the period containing `today`; the current week's or year's section plays it on whichever day's page it is tapped from. It also plays only when the section settles on time, within `REWARD_GRACE_MS` of being due: a section left settling because its page was turned away or the app went to the background is achieved without it, and the moment is still owed to the next tap that completes it. The root layout does not wait for this store to rehydrate, since no first render reads it.

Rejected: reading settledness from stamps alone (a complete section whose newest `updatedAt` is younger than the window), which needs no new state but cannot tell a tap from a fresh merge, and unsettles an achieved header on a title edit; a different gesture for missed, which the issue rules out; and keeping `played` in memory, which replays the moment after a restart. Known limits: someone who rests longer than 1.5 s on done before tapping on to missed sees the header and spends that period's reward moment, and a second device plays its own moment if a section is un-achieved and re-achieved there.
